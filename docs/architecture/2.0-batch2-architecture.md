# GPA Tracker 2.0 — Batch 2 架構設計（純設計）
版本：草案 v0.1（供審閱，尚未實作）
日期：2026-10-22
範圍：香港高級文憑 / 副學士 / 大學學士的 GPA Rule Profile、Assessment 與正式等級分離、不透明評分情境、Attendance Policy 預留。

---

## 0. 設計原則

1. 設計與實作分離：本文件只定義資料模型、模組分工、Migration、介面流程、驗收標準；不修改正式資料庫、不部署。
2. 不虛構規則：任何院校條例若未取得官方原文並逐項核對，狀態一律為 unknown；unknown 規則不得被引擎靜默套用。
3. 向後兼容：現有 terms / courses / assessments 與雲端 schema 不破壞；新增規則層為可選。
4. 分層引擎：Assessment（分數）→ Grading Policy（分數→等級）→ GPA Aggregation（學期/CGPA）→ Scenario（情境），各層可獨立測試。
5. Attendance 先設計後實作：本批只納入資料模型與政策介面，缺席額度、風險預測留待獨立 Batch。

## 1. 核心概念：Rule Profile（規則設定檔）

Rule Profile 是「某院校 × 某學歷層級 × 某入學年份 × 某規例版本」的一組可版本化規則。

身份鍵（Identity）：
    (institutionId, qualificationLevel, admissionYear, regulationVersion)

狀態（status）：
    verified   — 已對照官方原文並逐項核對
    partial    — 部分欄位已核實，其餘 unknown
    custom     — 使用者自訂（非官方）
    deprecated — 已被新版規例取代
    unknown    — 未核實（預設，不得自動套用）

### 1.1 Institution（院校）
    {
      "id": "vtc",
      "name": "職業訓練局 (VTC)",
      "officialDomain": "vtc.edu.hk",
      "country": "HK",
      "status": "unknown"
    }

### 1.2 QualificationLevel（學歷層級）
    {
      "id": "higher-diploma",
      "label": "高級文憑",
      "level": "sub-degree",
      "typicalYears": 2
    }
    另有 associate-degree（副學士）、bachelor（學士）。

### 1.3 RegulationVersion（規例版本）
    {
      "id": "vtc-hd-2024-v1",
      "institutionId": "vtc",
      "qualificationId": "higher-diploma",
      "admissionYear": 2024,
      "version": "v1",
      "status": "unknown",
      "verifiedAt": null
    }
    規則以「入學年份」為錨，避免新生套用舊規例。

### 1.4 GradeScale（Letter Grade 與 Grade Point）
    {
      "scaleId": "vtc-hd-2024-v1-scale",
      "grades": [
        { "letter": "A",  "gp": 4.0,  "minMark": 75 },
        { "letter": "A-", "gp": 3.7,  "minMark": 70 },
        { "letter": "B+", "gp": 3.3,  "minMark": 67 }
      ],
      "passGrade": "D",
      "passMark": 40,
      "status": "unknown",
      "sources": []
    }
    ※ 上列數值僅為「現有程式硬編碼值」的佔位，未經核實，正式 profile 必須填 verified 或保持 unknown。

### 1.5 GpaRules（學期 GPA / CGPA）
    {
      "termGpaFormula": "sum(gp * credits) / sum(credits)",
      "cgpaFormula": "all_terms_weighted",
      "includeExcludedCourses": false,
      "zeroCreditHandling": "ignore",
      "rounding": { "method": "half-up", "dp": 2 },
      "status": "unknown"
    }

### 1.6 PassAndRepeatRules（特殊及格與重修）
    {
      "passRule": { "type": "grade-at-or-above", "grade": "D" },
      "repeatRule": { "type": "replace", "keepBestAttempt": false, "capAtPassGrade": true },
      "supplementaryExam": { "allowed": true, "maxGradeAfterPass": "D" },
      "status": "unknown"
    }

### 1.7 AssessmentPolicy（分數與正式等級分離）
    {
      "mode": "score-based",
      "scoreToGrade": "policy-computed",
      "officialGradeOverride": true,
      "passComponents": { "CA": 40, "EA": 40 },
      "weightsMustSumTo": 100,
      "status": "unknown"
    }
    關鍵：正式等級（official grade）與計算等級（computed grade）分開儲存；GPA 只採用「正式等級」，計算值僅作預測/提醒。

### 1.8 VerificationMeta（來源與核實）
    {
      "status": "unknown",
      "verifiedAt": null,
      "verifiedBy": null,
      "sources": [
        { "url": "https://...", "title": "...", "accessedAt": "YYYY-MM-DD", "excerpt": "原文摘錄" }
      ],
      "notes": ""
    }
    規則不得無來源地標為 verified。

## 2. 實體關係（ER）

    Institution 1 ── * RegulationVersion * ── 1 QualificationLevel
    RegulationVersion 1 ── 1 GradeScale
    RegulationVersion 1 ── 1 GpaRules
    RegulationVersion 1 ── 1 PassAndRepeatRules
    RegulationVersion 1 ── 1 AssessmentPolicy
    RegulationVersion 1 ── 1 AttendancePolicy
    User 1 ── * UserRuleBinding （使用者選擇的院校/學歷/入學年份）
    Course * ── 1 RegulationVersion （可覆寫，預設沿用 UserRuleBinding）

## 3. 分層引擎（模組分工）

| 模組 | 職責 | 輸入 | 輸出 |
|---|---|---|---|
| AssessmentEngine | 依權重/滿分/得分計算加權分與組別百分比 | assessments, assessmentPolicy | secured, ca/ea 百分比, pending |
| GradingPolicyEngine | 分數 → 計算等級（依 GradeScale） | secured, gradeScale | computedGrade |
| GpaAggregationEngine | 學期 GPA、CGPA、重修替換 | courses, officialGrades, gpaRules | termGpa, cgpa |
| ScenarioEngine | What-if、不透明評分模擬 | assessments, target, policy | 情境結果（區間/必要分） |
| AttendanceEngine（後續） | 出席率、缺席額度、風險分級 | sessions, records, attendancePolicy | 出席率、風險等級 |
| RuleResolver | 依身份鍵解析 Rule Profile，unknown 時回傳 null | institution/qualification/year | profile 或 null |

檔案建議（實作階段）：
    public/rules/                          # 規則資料（JSON，版本化）
    public/js/engines/assessment.js
    public/js/engines/grading-policy.js
    public/js/engines/gpa-aggregation.js
    public/js/engines/scenario.js
    public/js/engines/attendance.js        # 後續批次
    public/js/rule-resolver.js

## 4. Migration 設計（純設計，未執行）

### 4.1 方案 A：JSONB 規則表（建議）
    create table public.rule_profiles (
      id text primary key,
      institution_id text not null,
      qualification_level text not null,
      admission_year int not null,
      regulation_version text not null,
      status text not null default 'unknown',
      profile jsonb not null,
      verified_at timestamptz,
      sources jsonb not null default '[]'::jsonb,
      created_at timestamptz not null default now(),
      updated_at timestamptz not null default now(),
      unique (institution_id, qualification_level, admission_year, regulation_version)
    );

    create table public.user_rule_bindings (
      user_id uuid primary key references auth.users(id) on delete cascade,
      institution_id text,
      qualification_level text,
      admission_year int,
      regulation_version text,
      updated_at timestamptz not null default now()
    );

    alter table public.courses
      add column if not exists rule_profile_id text references public.rule_profiles(id);

優點：規則 schema 可演進、易匯入/匯出、RLS 簡單（rule_profiles 可公開唯讀，user_rule_bindings 只限本人）。

### 4.2 RLS
- rule_profiles：select 開放（using (true)），寫入只限 service role。
- user_rule_bindings：auth.uid() = user_id 全 CRUD。

### 4.3 與現有資料的相容
- 不改既有 terms/courses/assessments 欄位。
- 新增 courses.rule_profile_id（nullable）。
- 舊資料無 rule_profile_id → 使用 custom/unknown profile 或全域預設，不得假裝已核實。

### 4.4 Migration 檔案
    supabase/migrations/002_batch2_rule_profiles.sql
    — 全部 idempotent（create table if not exists / add column if not exists）。
    — 不刪任何既有資料。
    — 含 RLS policy 建立與 grant。

## 5. 介面流程

### 5.1 首次設定（Onboarding）
    選擇院校 → 選擇學歷層級 → 選擇入學年份 → 顯示對應 Rule Profile 狀態
    → 若 status=unknown，顯示「此規例尚未核實，GPA 計算結果僅供參考」警告
    → 儲存 user_rule_binding

### 5.2 科目
    - 建立科目時自動帶入 user_rule_binding 的 rule_profile_id。
    - 科目頁顯示：計算等級（computedGrade）、正式等級（officialGrade）、來源狀態。

### 5.3 正式等級輸入
    - 使用者可輸入「正式等級」（成績單上的 grade），GPA 以此為準。
    - 若未輸入，顯示「以計算值預測」並標示「預測」。

### 5.4 不透明評分情境模擬
    - 科目若 assessmentPolicy.mode = opaque：
      - 不顯示分數 → 改顯示「等級區間」或「必要條件」。
      - 模擬：假設某組別得分 X，最終等級可能落在哪些區間。
    - 情境結果必須標示為「模擬」，不得寫入正式 GPA。

### 5.5 Attendance（後續批次）
    - 每科可設定 attendancePolicy（來源可為 rule_profile 或自訂）。
    - 介面預留：課堂紀錄、出席率、遲到、請假、缺席額度、風險等級。

- 若 policy 為 unknown → 只顯示實際出席率，不給風險等級。

## 7. 官方規則來源與核實狀態

### 7.1 核實等級
    verified   — 官方原文逐項核對，附 URL + 存取日期 + 摘錄
    partial    — 部分核實
    custom     — 使用者自訂
    deprecated — 已失效
    unknown    — 未核實（預設）

### 7.2 核實流程（每一項規則都要做）
    1. 找到官方來源（院校官網 / 學生手冊 PDF / 學術規例頁）。
    2. 擷取原文摘錄（含章節/頁碼）。
    3. 填入 sources[]（url, title, accessedAt, excerpt）。
    4. 由第二位審查者覆核。
    5. 才把 status 由 unknown 改為 verified/partial。
    6. 未完成上述步驟者，一律 unknown。

### 7.3 待核實清單（初始全部 unknown）
| 院校 | 學歷層級 | 入學年份 | 待核實項目 | 狀態 |
|---|---|---|---|---|
| VTC / IVE | 高級文憑 | ? | Grade/GP 對照、CA/EA 門檻、重修 | unknown |
| 各大學（HKU/CUHK/PolyU/CityU/HKBU/Lingnan/EdUHK/HKMU） | 學士 | ? | Grade/GP、GPA 公式、重修 | unknown |
| 副學士（各院校） | 副學士 | ? | 同上 | unknown |

> 本設計不填入任何未核實數值。現有程式的 VTC/IVE 風格硬編碼（A=75/4.0 等）只作為 custom/unknown 佔位，不得標為官方。

## 8. 驗收標準（Batch 2 實作前需達標）

1. Rule Profile schema 定稿並通過 JSON Schema 驗證。
2. unknown 規則不得被引擎套用；UI 必須顯示未核實警告。
3. 五個引擎分離，各有獨立單元測試。
4. 正式等級與計算等級分離，GPA 只用正式等級。
5. 不透明評分情境只產生「模擬」，不寫入 GPA。
6. Attendance Policy 資料模型完成、可為 unknown；不套用任何預設門檻。
7. Migration 為獨立、idempotent、不刪資料；於測試 Supabase 專案驗證 RLS/交易後才可上正式。
8. 所有 verified 規則都附官方 URL + 存取日期 + 摘錄。

---

## 9. 風險與限制

1. 各院校規例可能每年變動 → 必須以入學年份 + 版本管理。
2. 部分院校 GPA 公式或重修規則不公開/不完整 → 保持 unknown。
3. 不透明評分無法精確預測 → 只能給區間/條件，不可給假精確值。
4. 規則核實需要人工審查與官方原文，無法由程式自動完成。
5. Attendance 政策各院校差異大，且部分只寫在課程層級 → 必須可按院校/科目調整。
