## 1. Rule Profile 模型（修訂）

### 1.0 三層覆寫（Institution → Programme → Subject）
身份優先次序（由廣到窄）：
    L1  Institution + QualificationLevel + AdmissionYear + RegulationVersion
    L2  Programme/Course-of-study 覆寫（例如 CUHK 某課程的特別 GPA 規則）
    L3  個別 Subject 覆寫（例如某科 excluded from GPA、或以 pass/fail 計）

解析規則：RuleResolver 由 L3 → L2 → L1 逐層覆寫（override），
每一層可只覆寫部分欄位（partial override）。

    RuleProfile {
      identity: { institutionId, qualificationLevel, admissionYear, regulationVersion },
      scope: "institution" | "programme" | "subject",
      scopeRef: null | { programmeId } | { subjectCode },
      fields: { ... },          // 可只含部分欄位
      itemStatus: { fieldPath: "verified" | "partial" | "unknown" | "custom" }
    }

### 1.1 逐項狀態（不是整套一個狀態）
每個規則欄位獨立記錄狀態與來源：
    itemStatus: {
      "gradeScale": "verified",
      "gpaFormula": "unknown",
      "repeatRule": "unknown",
      "excludedCourses": "partial",
      "scoreToGrade": "unknown",
      "attendancePolicy": "unknown"
    }
    itemSources: {
      "gradeScale": [ { url, title, accessedAt, excerpt } ]
    }
一項 verified 不代表其他項已核實。

### 1.2 部分計算（Partial Computation）
引擎必須能「只計算已核實且不依賴 unknown 規則」的部分：
- 若 gradeScale（等級→積點）verified 且 gpaFormula verified，但 repeatRule unknown：
  → 可計算「不涉及重修」的 Term GPA / CGPA；重修科目標示為 unknown、不納入或另列。
- 若 gpaFormula unknown → 不計算 GPA，只顯示等級。
- 若 excludedCourses unknown → 只計算「明確計入」的科目，並列出未確定科目。
輸出必須含：
    { value, computedFields[], skippedFields[], status }

### 1.3 分數 / 預測 / 正式 三層分離
    assessmentScore  : 評核原始分數（front-end 計算）
    computedGrade    : GradingPolicy 由分數推算的等級（預測）
    officialGrade    : 成績單正式等級（權威）
GPA 只採用 officialGrade；computedGrade 只作預測，不得寫入 GPA。
若 scoreToGrade unknown → computedGrade 為 null（不推測）。

### 1.4 Attendance Policy（擴充）
支援按「節數 / 分鐘 / 課堂類型」計算，並涵蓋：
    - 出席 (present)
    - 遲到 (late, 可設 lateAfterMinutes)
    - 早退 (earlyLeave, 可設 earlyLeaveBeforeMinutes)
    - 請假 (leave, 可分類 sick/official/personal)
    - 取消課堂 (cancelled，不計入分母)
    - 缺席 (absent)
計算單位可選：session（節數）或 minute（分鐘）或 hybrid。
    attendancePolicy {
      countingUnit: "session" | "minute" | "hybrid",
      sessionMinutes: null,
      lateAfterMinutes: null,
      lateWeight: null,
      lateCountsAsAbsent: null,
      earlyLeaveWeight: null,
      leaveCountsAsAbsent: null,
      cancelledExcluded: true,
      attendanceThresholdPercent: null,
      absenceQuotaSessions: null,
      absenceQuotaMinutes: null,
      classTypes: { lecture: {...}, lab: {...}, tutorial: {...} },
      riskTiers: null,
      status: "unknown",
      sources: []
    }
風險預測只用該科 policy；policy unknown → 只顯示實際出席率，不給風險等級。

## 2. 規則表寫入權限（修訂）
- rule_profiles（公共官方規則）：只有 service role / server-side 可寫；
  anon 與 authenticated 只有 SELECT。
- 不可只靠前端隱藏編輯按鈕。
- 驗收必須包含「普通登入使用者嘗試 INSERT/UPDATE/DELETE 規則 → 必須失敗」的 SQL 測試。

## 4. Migration 設計（修訂）
### 4.1 資料表
    rule_profiles (
      id text primary key,
      institution_id text not null,
      qualification_level text not null,
      admission_year int not null,
      regulation_version text not null,
      scope text not null default 'institution',   -- institution | programme | subject
      scope_ref jsonb,                             -- {programmeId} 或 {subjectCode}
      profile jsonb not null,
      item_status jsonb not null default '{}',
      item_sources jsonb not null default '{}',
      schema_version int not null default 1,
      created_at timestamptz not null default now(),
      updated_at timestamptz not null default now()
    );
    create unique index on rule_profiles (institution_id, qualification_level, admission_year, regulation_version, scope, coalesce(scope_ref, '{}'::jsonb));
    user_rule_bindings (user_id pk, institution_id, qualification_level, admission_year, regulation_version, programme_id, updated_at)
    courses.rule_profile_id text null
    courses.subject_override jsonb null

### 4.2 RLS
    rule_profiles:  enable RLS;
      create policy rule_profiles_read on rule_profiles for select using (true);
      -- 不建立 insert/update/delete policy → anon/authenticated 無法寫入（fail closed）
    user_rule_bindings: auth.uid() = user_id 全 CRUD。

### 4.3 JSONB Schema 驗證
- 每個 profile 必含 schemaVersion。
- 以 JSON Schema（draft 2020-12）驗證：
    gradeScale.grades[] 需 letter + gp；gp 為 number。
    gpaFormula 為受支援的 enum。
    attendancePolicy.countingUnit 為 enum。
- 寫入時在 server-side 驗證（DB function 或 Edge Function），不可只靠前端。
- 讀取時 client 亦驗證；不合法 → 視為 unknown，不使用。

### 4.4 版本控制與相容性
- schema_version 欄位；舊 profile 由 migration 或 client adapter 升級。
- 提供 schema migration script 與相容性測試（舊 JSON → 新 schema 仍可讀）。
- 不相容變更需新表或新版本欄位，不可原地破壞。

### 4.5 Migration 檔案
    supabase/migrations/002_batch2_rule_profiles.sql
    — idempotent、不刪資料、含 RLS 與 grant。
    — 於測試 Supabase 專案驗證後才可上正式。

## 5. 介面流程（修訂）
- Onboarding：院校 → 學歷 → 入學年份 → 顯示逐項狀態（verified/partial/unknown）。
- 科目：可選擇 programme 預設或 subject 覆寫（excluded / pass-fail）。
- 成績：分數、預測等級、正式等級三欄；GPA 只用正式等級。
- 部分計算：清楚列出「已計算 / 因 unknown 未計算」的欄位。
- Attendance：每科可設定 countingUnit、late/leave/earlyLeave/cancelled 規則與門檻。
- 規則來源：顯示每項的 official source 與 verified 日期。

## 8. 風險
1. 多數院校官方文件自動存取受限（VTC 403/404、CUHK 手冊 JS 載入）→ 需人工擷取。
2. unknown 規則若被誤用會產生錯誤 GPA → 引擎必須 fail closed。
3. 三層覆寫增加解析複雜度 → 需完整測試。
4. Attendance 各院校差異大 → 必須可自訂，預設 unknown。
